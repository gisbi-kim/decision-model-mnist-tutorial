01 / THE QUESTION

Reading Digits and Selecting a Position

In the previous MNIST experiment, the model selected −1, STOP, or +1 to reach the target digit in an image. Here, the task changes: given an image of three handwritten digits and a natural-language instruction, the model selects the position that satisfies the instruction.

The four choices are LEFT, CENTER, RIGHT, and NONE. For example, “Choose the odd number in the red box” requires the model to consider the digit, box color, and parity. If no digit satisfies the condition, the correct choice is NONE.

What are you trying to check?

Even if the image is the same, we examine whether behavior changes when the sentence changes and whether judgment is maintained even in combinations of handwriting, expressions, and conditions that were not used for learning. This is not an experiment that learned Jev itself, but an experiment that performed supervised learning by attaching a Clef-type head to a Qwen-base model.

03 / MODEL

From images and sentences to actions

The model receives an image, instructions written by the user, and a description of the four options. Numerical answer labels are used only for data generation and evaluation and are not included in inference input.

→
ENCODERQwen3.5-0.8B + LoRA

DECISION HEADScore for each choice → Probability

Clef method of expressing Qwen JointSchemaHeadWhen passed to , logit for each selection appears. Find the probability with softmax and choose the largest value as the action. During training, LoRA and head are updated to reduce cross-entropy for correct answer actions. This is not an experiment that replicates Jev's RLCD.

04 / DATA DESIGN

Without giving the correct answer
teaching judgment

2,265 scenes and 18,048 instructions were used for training. 6,380 original MNIST images were used here. By connecting multiple instructions to one scene, we included the experience of changing where to select even for the same picture. In fact, 2,197 of the learning scenes have instructions with different correct answer actions.

Ambiguous multiple correct answers and ties for the maximum and minimum values were excluded. Small changes to color, number enlargement, border, and position were also added. The number was assigned for each possible condition

TRAIN18,048Weight Learning
VALIDATION1,128Select model
CALIBRATION752temperature calibration
TEST5,056final evaluation

The original training image ID was divided into train·validation·calibration before scene creation, and the final test consisted of the official MNIST test image. The original numeric images can be reused between test sets. “New expressions” and “new combinations” mean that they have not been seen in this fine-tuning, and the pre-training data of the base model has not been checked.

In combinatorial generalization, Red + Even + Maximumand Blue + Odd + Minimumwas excluded from learning and evaluated. Each attribute itself was learned in different combinations. In language generalization, two sentence structures each in Korean and English were excluded.

05 / TRAINING

Checkpoint selected through one-time learning and verification

6,000 steps were learned in batch 16 on RTX 4070 Ti SUPER. The training time including validation and checkpoint saving is 69.0 minutes and does not include the initial model download/loading and data encoding time. A BF16-base model was used without 4-bit quantization, and both rank and alpha of LoRA are 16.

training machine Windows 11 Education, AMD Ryzen 7 9800X3D, RAM approx. 61.6 GiB, NVIDIA RTX 4070 Ti SUPER 16 GBIt was. 4.28% is a value with the number of parameters of the model including the existing Qwen + additional LoRA + new head as the denominator. This does not mean that the existing Qwen weighting of 4.28% was directly modified. LoRA alone is about 1.21% of the total and new head is about 3.07%. The figures are learning records and was based on public safetensors.

The learning rate was LoRA 2×10⁻⁴, head 1×10⁻⁴, and AdamW, cosine scheduler, warmup 60 steps, and weight decay 0.01 were used. After generating the location of the correct answer for each scene, the model score was calculated using images, instructions, and choices, and the cross-entropy of the correct answer behavior was minimized. learning codeWow data generation codeYou can check it here.

In the selected step 2,000, 253 of the 256 fixed validation lines were correct. In subsequent steps, there is a section where the same highest accuracy was achieved. As a result of adjusting the temperature from separate calibration data, the NLL was lowered from 0.1806 to 0.1279. Correction scales the probability, and positive temperatures in this setting do not change the ranking of the highest action.

Learning amount and number of data are different

6,000 steps × batch 16 is 96,000 sample exposures. This should not be interpreted as 96,000 different examples, as you may see the same training rows again.

To what extent was it correct?

Below is the final test performed with the saved weights. The baseline combines a digit recognition CNN and rules. The baseline also knows the location of fixed slots and a limited template vocabulary, and is configured to parse test sentence meaning. This comparison alone cannot prove the need for free language understanding or VLM.

The confidence interval is a scene-level bootstrap. It does not fully reflect the dependency resulting from the reuse of original numerical images between scenes.

Are you using both images and sentences?

In the small diagnostic subset, it was 100% with the original input, 21.88% with blank images, 23.44% with shuffled images, and 26.56% with blank instructions. This is an input removal test where scores are based on the original correct answer, and the results of removing input should not be interpreted as the accuracy of the new normal task.

How did inference speed compare?

For the same 16 inputs, both CPU and CUDA behavior were consistent. The median values ​​were CPU 770.2ms and CUDA 70.5ms. It is a measurement of the environment, including preprocessing and synchronization, but excluding model loading. CPU is float32 and CUDA is bfloat16, so the same speed is not guaranteed on other devices. Speed ​​comparisons with text generation methods were also not performed.

07 / LIMITS

Could be wrong with a high probability

“The smallest odd number in the blue box... if it is not there, it is NONE”
Correct answer NONE · Prediction RIGHT · 98.3%

This data is an educational benchmark with predetermined placement, color, and sentence conditions. Performance claims cannot be extended to random placement, unfamiliar handwriting, instructions with multiple correct answers, or sentences outside the scope of learning. Ablation that only learned the head and a separate text generation baseline were not performed. Therefore, we cannot conclude that head or VLM are inherently more accurate or faster than the other alternatives.

The actual distribution app does not automatically determine the correct answer to free instructions. Model probability may be a clue to judge reliability, but it is not a value that guarantees safe behavior. Full failure cases and evaluation recordsLet's take a look together.
